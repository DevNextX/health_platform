# 产品需求文档：支持微软账号登录 (Microsoft Login Integration)

## 1. 需求概述 (Summary)
**目标**: 在现有健康平台的登录认证体系中，引入“微软账号登录 (Sign in with Microsoft)”功能（基于 OAuth 2.0 / OpenID Connect），实现单点登录 (SSO)，降低用户的使用门槛并提升账户安全性。

## 2. 核心决策与业务规则 (Business Rules)
1. **账号支持范围**: 支持所有的微软账号（Multi-tenant 模式），包括个人账号（`@outlook.com`, `@hotmail.com` 等）以及任何企业/组织的 Entra ID (Azure AD) 账号。
2. **新老账号绑定**: 如果用户使用微软账号授权登录，且授权返回的 Email 地址在系统数据库中已存在（即通过本地邮箱密码注册过），系统应**自动将该微软账号与已有本地账号绑定**，允许用户无缝登录。
3. **静默注册机制**: 如果是全新用户（即该微软账号返回的 Email 在系统中不存在），系统将**自动为其静默注册**，并授予默认的普通用户角色（`USER` 级别），登录成功后直接跳转至系统。无需用户手动补全注册表单。
4. **延迟同步资料**: 在当前迭代版本 (v1) 中，仅获取足够完成静默注册和唯一性校验的关键标识（如邮箱和唯一 Subject ID）。用户的姓名、头像等个人资料（Profile）本期**不同步**，留作后续版本优化。

## 3. 用户故事 (User Stories)
- **作为已注册用户**，我希望在登录页面点击“通过微软账号登录”，系统能认出我的邮箱并直接登入，不用我回忆本地密码。
- **作为全新用户**，我希望能够直接用我的微软账号一键登录平台，省去繁琐的填表注册流程。

## 4. 验收标准 (Acceptance Criteria)
### 4.1 前端 UI 与交互 (Frontend)
- [ ] 登录页面增加明显的 "Sign in with Microsoft" 按钮。
- [ ] 点击按钮后，正常跳转至微软授权端点 (Microsoft identity platform endpoint)。
- [ ] 授权完成后，前端能够捕获回调 (Callback) 并向后端发起校验请求；请求期间展示 Loading 状态。
- [ ] 整体体验应做到平滑，认证失败时要有明确的提示（例如“授权已被取消”或“网络错误”）。

### 4.2 后端逻辑 (Backend)
- [ ] 新增生成微软登录授权 URL 的 API 接口。
- [ ] 新增处理微软授权回调的代码（验证 Authorization Code 或 Token，向微软换取 User Info / Email）。
- [ ] 实现核心绑定/注册逻辑：
  - 查询数据库中是否已存在该 Email。
  - 若存在：下发当前用户的系统 JWT Token。
  - 若不存在：在数据库中插入新用户（默认角色 `USER`），然后下发系统 JWT Token。

### 4.3 数据与安全 (Data & Security)
- [ ] 确保处理微软账号的凭证时不在前端暴露 App Secret 等敏感信息，所有的通信验证都在后端完成。
- [ ] 需要记录第三方登录方式的数据字段可能需要扩充，例如通过 `auth_provider` 和 `provider_account_id` 区分。

## 5. 本期不包含 (Out of Scope)
- 微软账号解除绑定功能。
- 微软账号的个人资料（姓名、头像等）同步。
- 绑定除微软以外的第三方账号（如 Google, GitHub 等，预留扩展性即可）。
