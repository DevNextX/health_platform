# Requirement: 家庭成员既往病史管理 MVP

## 1. 背景与价值
- **用户故事**：作为家庭健康平台用户，我希望为每个家庭成员维护既往病史，以便在查看健康记录时有完整背景，并支持长期健康管理。
- **业务价值**：
  - 将平台能力从“单次指标记录”提升为“连续健康档案管理”。
  - 强化家庭场景价值，支持成员级独立病史维护。
  - 在慢性病与服药背景下，提高血压/心率数据解读的准确性与可解释性。

## 2. 范围与边界
- **范围内（MVP）**：
  - 新增“家庭成员级”既往病史能力（每个成员独立维护）。
  - 支持病史条目的新增、查看、编辑、删除。
  - MVP 必填字段：
    - 发病时间
    - 疾病名称
    - 病情描述
    - 是否仍存在（是/否）
    - 是否服药（是/否）
  - 双入口：
    - 入口 A：新增健康记录流程中的附加入口/区块。
    - 入口 B：独立的既往病史管理页面。
  - 前端与后端均属于本期交付范围。
- **范围外（当前 MVP 不包含）**：
  - 标准疾病编码体系（如 ICD）接入。
  - 详细用药管理（药名/剂量/频次）。
  - 临床诊断建议或自动决策。
  - 跨成员共享病史模板。

## 3. 验收标准（AC）
- [ ] AC1：每个家庭成员可独立维护病史，切换成员后仅显示对应成员病史数据。
- [ ] AC2：用户可创建病史条目，包含发病时间、疾病名称、描述、是否仍存在、是否服药。
- [ ] AC3：用户可编辑与删除已有病史条目。
- [ ] AC4：用户可从“新增健康记录流程”和“独立病史页”两处访问病史能力。
- [ ] AC5：任一入口创建/修改的数据，在另一入口可立即一致可见。
- [ ] AC6：后端可持久化并正确返回全部 MVP 字段。
- [ ] AC7：系统可拦截必填项为空与非法时间格式。
- [ ] AC8：该功能上线后不影响现有健康记录新增/列表/仪表盘流程。

## 4. 非功能性要求
- **安全与隐私**：
  - 既往病史属于敏感健康信息，必须遵循现有权限与隐私控制。
  - 仅授权用户可访问其有权限的家庭成员病史数据。
- **易用性**：
  - MVP 表单保持轻量、易理解。
  - 允许用户稍后补充，不阻塞核心健康记录提交流程。
- **一致性**：
  - 遵循现有中英文国际化机制与 UI 风格。
  - 双入口行为与数据规则保持一致。
- **可靠性**：
  - 保证成员归属关系与状态字段的数据完整性。

## 5. 下一阶段建议（Post-MVP）
- 当“是否仍存在=否”时，增加“结束时间”可选字段。
- 增加严重程度（轻/中/重）。
- 增加可展开的用药详情（药名、频次等）。
- 在仪表盘增加“进行中病史摘要卡”。
- 导出时增加“是否包含病史信息”开关。

## 6. 设计前待确认问题
- 发病时间在 MVP 阶段是否仅支持“日期”，还是支持“年月”。
- 疾病名称是仅自由输入，还是“自由输入 + 常见疾病快捷选择”。
- 不同角色对病史模块的可见范围是否存在差异化要求。
