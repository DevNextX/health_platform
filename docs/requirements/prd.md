## 执行摘要

让超级管理员能够定义并维护健康阈值，使平台在不调整硬性输入限制的前提下，根据行业标准或医生建议快速更新“正常”与“异常”判定逻辑。阈值与可视化、数据校验和家庭指导体验紧密相连，配置后即可同步影响健康记录的展示与提醒。

通过可配置阈值，家庭成员在仪表盘中获取一致、可信的异常提示，避免因为不同地区或医疗观点差异而产生的争议，同时维持既有 30–250 mmHg（血压）与 30–150 bpm（心率）的安全输入范围和数据完整性。

### 独特价值

灵活的健康阈值治理：超级管理员可将可信的医疗指导快速落地到所有图表、洞察与提醒中，平台继续阻止不合理输入，但能即时反映不断演进的健康标准，为家庭成员提供精准、一致的异常提示。

## 项目分类

**技术类型：** 具备多租户管理员能力的 Web 应用  
**领域：** 家庭健康数据追踪  
**复杂度：** 高（受监管的健康数据与安全敏感阈值）

平台基于 Flask/React 架构，用户以家庭为单位登录、录入血压和心率等记录，并在可视化仪表盘查看趋势。超级管理员负责全局配置，家庭管理员与成员消费前端视图。系统已执行硬性输入校验（血压 30–250 mmHg、心率 30–150 bpm），并对异常读数进行高亮提示。

### 领域背景

由于产品直接呈现个人健康数据并提供参考性提示，必须契合医疗规范并避免误判。全球高血压标准不断变化（如 120、130 或 140 mmHg 的分界），不同地区、不同医生的建议各异。通过引入健康阈值配置，平台可在保持监管要求的硬性边界之上，灵活调整“正常/异常”标准，避免频繁上线部署或产生误导。

## 成功标准

- 超级管理员可在数秒内完成阈值更新，无需工程更改或重启服务。
- 仪表盘依照新阈值高亮异常读数，与基线相比不增加误报率。
- 审计日志完整记录阈值变更的操作者、时间与修改内容。
- 录入表单仍严格拒绝超出 30–250 mmHg 与 30–150 bpm 的非法数据。
- 90% 以上的受访家庭成员认为阈值说明提升了对系统判断的信任度。

## 领域特定要求

- **监管对齐：** 默认阈值应参考权威指南并记录变更历史，便于审计。
- **患者安全：** 不论阈值如何调整，硬性输入范围 30–250 mmHg、30–150 bpm 不可修改。
- **审计追踪：** 每次阈值发布需记录管理员、时间、变更前后数值及理由。
- **可扩展性：** 数据模型需预留空间，以支持未来的成员级阈值或地区预设。

此处的要求将直接影响后续的功能与非功能设计。

## Web 应用特定要求

- 阈值设置界面位于超级管理员门户，按收缩压、舒张压、心率进行分组展示。
- 导航调整：原“Settings” 菜单重命名为 “User Setting”，保留 “User Management”，新增仅超级管理员可见的 “Super Admin Setting” 页面作为阈值治理入口。
- Flask 后端提供阈值配置的 CRUD 接口，并维护版本历史。
- React 前端通过现有服务层获取配置，可在客户端短暂缓存，并在配置发布后及时失效刷新。
- 当前阈值应用于整个租户，数据模型需支持未来传入租户或成员维度的参数。
- 权限控制：仅超级管理员可修改阈值，其余角色均为只读。

## 用户体验原则

- **信息清晰：** 在任何图表或卡片中，用一致的颜色、图例与提示语体现“正常 / 临界 / 异常”。
- **透明可信：** 提供活动阈值的数值、来源与最近更新时间，增强用户信任。
- **操作高效：** 配置界面采用 Ant Design 表单控件与即时校验，降低误操作。

### 关键交互

1. 超级管理员在侧边菜单的 “Super Admin Setting” 页面进入“健康阈值”设置，调整数值、预览影响并一键发布。
2. 家庭成员通过重命名后的 “User Setting” 页面管理个人语言与密码，录入血压或心率时表单提示当前阈值下的状态，并阻止安全范围外的输入。
3. 仪表盘刷新后，按照新阈值高亮异常数据，并提供悬浮说明与版本信息；“User Management” 仍用于管理员重置用户密码。

## 功能需求

### 能力分组与功能编号

**FR1 – 全局阈值治理：** 超级管理员可创建、编辑并发布血压与心率的健康阈值，系统始终执行硬性输入范围。

**FR2 – 版本历史：** 超级管理员可查看阈值变更记录（操作人、时间、前后差异）。

**FR3 – 安全预览：** 发布前可在示例数据中预览新阈值对“异常/正常”判定的影响。

**FR4 – 即时下发：** 一旦发布，新阈值会同步至所有家庭仪表盘与后端服务，无需用户重新登录。

**FR5 – 录入校验：** 新增/编辑健康记录时，表单提示当前阈值下的状态，并继续阻止超出 30–250 mmHg 与 30–150 bpm 的非法输入。

**FR6 – 仪表盘高亮：** 仪表盘用颜色、徽标和无障碍标签突出异常读数。

**FR7 – 历史洞察：** 用户可按“正常 / 异常”筛选历史趋势，快速发现模式变化。

**FR8 – API 输出：** 外部接口与导出文件包含读数“状态”字段，反映生成时的阈值配置。

**FR9 – Self/自己 保护：** 阈值逻辑对“Self/自己”成员同样适用，同时保持其不可删除/修改的保护策略。

**FR10 – 审计导出：** 超级管理员可导出阈值配置的历史 CSV/JSON 用于合规审查。

## 非功能需求

### 性能

- 后端读取阈值需在 50ms 内完成，并启用内存缓存避免影响仪表盘加载。
- 发布阈值后，缓存需在 5 秒内失效，确保前端立即获取最新配置。

### 安全

- 阈值接口必须使用 JWT 鉴权，并在 service/manager 双层校验超级管理员角色。
- 审计日志记录包括 IP、User-Agent以及修改前后数值。

### 可扩展性

- 数据模型需支持未来按租户、家庭或成员存储阈值，无需大规模重构。

### 可访问性

- 颜色提示需符合 WCAG 4.5:1 对比度，提供文本标签与图标辅助色弱用户理解。

### 集成

- CSV 导出与 API 响应需包含阈值版本号，便于下游系统追踪判定依据。
