# 需求：健康阈值治理 (Threshold Configuration Governance)

## 基本信息
- **标题**：超级管理员健康阈值配置与全局治理
- **保存路径**：`/docs/requirements/req-threshold-config-governance.md`
- **状态**：已澄清 (Clarified)
- **背景**：目前系统使用硬编码的阈值判断健康状态，无法适应不同医疗标准或调整需求。需要赋予超级管理员配置“健康范围”的能力。
- **业务价值**：提升平台灵活性与专业性，确保家庭成员获得的健康提示符合当前认可的医疗标准，消除因标准差异导致的误解。

## 范围
- **范围内**：
    - 超级管理员全局配置收缩压、舒张压、心率的“健康范围”。
    - 仪表盘根据配置动态展示“健康”、“临界”、“异常”状态（颜色/标记）。
    - 默认阈值预设（收缩压 90-120-140，舒张压 60-80-90，心率 60-100）。
    - 真实数据预览功能（在发布前查看新阈值效果）。
    - 审计日志记录与 CSV 导出。
    - API 路径规范化 (`/superadmin/`) 与安全校验。
- **不包含**：
    - 租户级或用户级独立阈值配置（MVP 仅支持全局）。
    - 修改系统硬性安全输入范围（30-250 mmHg, 30-150 bpm 保持不变）。
    - 复杂的后端主动推送/WebSocket 通知（前端刷新生效即可）。

## 验收标准 (Acceptance Criteria)

### 1. 阈值配置 (Configuration)
- **AC1.1**: 超级管理员可在"Super Admin Setting"页面配置以下阈值：
    - 收缩压：健康下限 (healthy_min)、健康上限 (healthy_max)、临界上限 (borderline_max)
    - 舒张压：健康下限 (healthy_min)、健康上限 (healthy_max)、临界上限 (borderline_max)
    - 心率：健康下限 (healthy_min)、健康上限 (healthy_max)（心率不设临界上限）
- **AC1.2**: 输入校验：
    - 对于血压指标：健康下限 < 健康上限 < 临界上限
    - 对于心率指标：健康下限 < 健康上限
    - 所有配置值必须在硬性安全范围内（血压 30-250 mmHg，心率 30-150 bpm）
    - 前端应实时校验并提示错误，后端需二次校验以确保数据完整性
- **AC1.3**: 系统初始化或重置时，自动应用默认值：
    - 收缩压: 90 (健康下限) - 120 (健康上限) - 140 (临界上限) mmHg
    - 舒张压: 60 (健康下限) - 80 (健康上限) - 90 (临界上限) mmHg
    - 心率: 60 (健康下限) - 100 (健康上限) bpm（心率无临界上限）

### 2. 仪表盘显示 (Dashboard Visualization)
- **AC2.1**: 仪表盘图表与列表需根据当前生效的阈值判定每条记录的状态。
- **AC2.2**: 状态判定逻辑（三层分级模型）：
    
    **对于血压指标**（收缩压/舒张压）：
    - **健康 (Healthy)**: healthy_min ≤ 值 ≤ healthy_max → 显示绿色
    - **临界 (Borderline)**: healthy_max < 值 ≤ borderline_max → 显示橙色/黄色
    - **异常 (Out of Range)**: 值 < healthy_min 或 值 > borderline_max → 显示红色
    
    **对于心率指标**（仅两层分级）：
    - **健康 (Healthy)**: healthy_min ≤ 值 ≤ healthy_max → 显示绿色
    - **异常 (Out of Range)**: 值 < healthy_min 或 值 > healthy_max → 显示红色
    
    *说明：心率指标不设临界区间，因临床意义上心率异常的分界更为明确。*
- **AC2.3**: 阈值更新后，用户刷新仪表盘即可看到基于新标准的状态变化。

### 3. 预览与发布 (Preview & Publish)
- **AC3.1**: 在保存/发布前，管理员可点击“预览”，系统基于当前真实数据（或抽样）展示新阈值下的分布变化（如：原 5 条异常，新标准下变为 8 条）。
- **AC3.2**: 确认发布后，配置立即写入数据库并生效。

### 4. 审计与安全 (Audit & Security)
- **AC4.1**: 仅具有 `SUPER_ADMIN` 权限的用户可访问配置接口。
- **AC4.2**: API 路径应位于 `/api/v1/superadmin/` 下。
- **AC4.3**: 每次变更需记录：操作人 ID、时间、旧阈值、新阈值。
- **AC4.4**: 支持导出审计日志为 CSV 格式。

## 边界场景
- **输入冲突**: 
    - 尝试设置 healthy_min > healthy_max，前端应阻止提交
    - 尝试设置 healthy_max > borderline_max（血压），前端应阻止提交
- **硬性限制冲突**: 
    - 尝试设置临界上限 > 250 mmHg，后端应拒绝并返回 400 错误
    - 尝试设置健康下限 < 30，后端应拒绝
- **空值处理**: 某些记录可能缺省心率，计算状态时应忽略该字段，不影响血压状态判定
- **历史数据兼容**: 阈值变更不影响历史记录的原始数值，仅改变状态判定结果

## 约束与非功能需求
- **安全性**: 严格的 RBAC 控制，确保普通管理员无法修改。
- **性能**: 阈值读取应有缓存（如内存缓存），避免每次请求查库；更新后缓存需及时失效。
- **UI 风格**: 遵循 Ant Design 现有风格，保持一致性。
- **兼容性**: 历史数据不被修改，仅展示状态发生变化。

## 风险 / 问题
- **用户困惑**: 阈值变更后，用户可能会发现昨天的“健康”记录今天变成了“异常”。建议在仪表盘显著位置提示“当前健康标准版本/日期”。
