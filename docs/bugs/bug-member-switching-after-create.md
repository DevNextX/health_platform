# Bug Report: 创建家庭成员后无法及时切换，导致无法为该成员录入数据

## 基本信息
- 类型: Bug
- 严重级别: Critical
- 优先级: High
- 影响范围: 家庭成员切换、健康记录、既往病史录入流程

## 问题描述
用户创建新的家庭成员后，顶部成员选择器未及时刷新，导致新成员无法被选择。结果是用户只能继续对当前成员（通常是 Self）录入健康记录和既往病史，无法完成家庭场景核心流程。

## 复现步骤
1. 登录普通家庭账号。
2. 进入“成员管理”新增一个家庭成员。
3. 尝试在右上角成员选择器中切换到新成员。
4. 再进入“健康记录”或“既往病史”尝试录入。

## 实际结果
- 新成员在当前会话中可能不会出现在选择器中（需刷新页面后才出现）。
- 无法立即切换并对该成员录入数据。

## 预期结果
- 新增成员后，成员选择器应立即可见并可切换。
- 根据产品决策：不自动切换，但应明确提示用户手动选择新成员。

## 根因分析
- `MemberSelector` 初始加载后缺乏成员变更事件订阅，列表不会随 `Members` 页面的新增/删除动作自动更新。
- 选择器数据源刷新时机不足（仅首次或语言切换触发）。

## 修复方案
- 在 `Members` 页面创建/删除后派发 `members:changed` 事件。
- 在 `MemberSelector` 监听该事件并重新拉取成员列表。
- 在选择器下拉打开时主动 refresh 一次，进一步降低陈旧数据概率。
- 按产品要求：创建成功后不自动切换，仅给出“请切换成员后再录入”的提示。

## 影响与回归
- 影响家庭用户核心路径，属于高优先级功能性缺陷。
- 建议回归：创建成员、删除成员、切换成员、录入健康记录/既往病史全链路。
